# 四張地圖重做驗收說明（2026-10-20）

作者的標準：「像十一分鐘、起跑總在開始前那種標準」。回饋原文見 `design/回饋-1019.jsonl`（物件歪歪扭扭、不整齊、收音機上緣被切、沒有設計圖與物件尺寸、側台門與後門沒畫、任務點走不過去）。
做法照 `rpg-map-playbook.md` 與十一分鐘的 `objects_gen.py`：設計檔（格子座標）→ 色塊 → 畫風定錨 → 地面 → 逐物件生成 → 機械閘門 → 切段 → 合成 → 引擎實測。

## 這次的結構

| 檔案 | 做什麼 |
|---|---|
| `art/objects_<map>.yaml` | 設計檔。每個物件有 `foot` 佔地格、`up` 往上長幾格、`type`（共用的圖）、描述；後台另有 `checks`（要藏的格子、負控制要拿掉的牆） |
| `art/mapgen.py` | 新管線。`style`（整間房定錨）→ `ground`（地面＋對位）→ `gen`（逐物件）→ `cut`（切段）→ `review`（合成預覽）→ `audit`（驗收表） |
| `art/occl_check.py` | 四張地圖通用的遮擋驗證（含負控制） |
| `tests/map_check.py` | 從 build 出來的 project.json 驗：每格事件、導引目標、跳轉落點走得到 |
| `tests/map_walk.mjs` | 實機：點左上角「遊戲任務」讓主角自己走過去，九條路線 |
| `tests/map_shots.mjs`、`tests/map_cells.mjs` | 進引擎截圖；把主角擺到指定格子再截圖 |
| `art/preview_build.py` | 把 build 導到 `dist-maps/`，不動主對話的 `dist/` |

相機規格全部統一：固定 3/4 俯視（約 50 度，從南邊看）、光從左上、物件邊緣與畫面邊緣平行。畫風是暖色手繪繪本風（不是像素風），沿用化妝間定錨，其他三張用化妝間定錨當畫風參考。

## 門（2026-10-20 作者：「門製作得非常奇怪」）

**問題**：原本三扇側牆的門（後台西牆的側台門、東牆的後門、觀眾席舞台旁的入口）都是 1×3 的窄條，貼在地圖最外緣、在地板範圍之外，像貼紙，不像嵌在牆裡。
**規則**：相機從南邊看，只看得到朝南的牆面，所以門一律做在朝南的牆面上；門嵌在牆裡、跟牆同一個畫面；有門框、門板、門前的腳墊或門階；六扇門大小一致（含門框約 1.7×2.9 格，門板約 1.3×2.6 格）；每扇門前兩格都是觸發點、走得到。
**怎麼改**
- 後台的側台門與後門：切進一樓北邊的陽台前緣磚牆（朝南），兩扇相距 8 格（x3–4 與 x11–12），都離樓梯很遠。為了放得下約 3 格高的門，磚牆面加高到 4 列，一樓縮成 3 列。
- 觀眾席通後台的門：**沒有照指示放在舞台前緣**，改放在舞台後牆（紅絨幕旁，朝南）。原因：舞台前緣的木裙只有 3 格高，其中 1 格是腳燈，門板最多 1.8 格，比人物矮一大截，上面還頂出一個方塊，像小亭子。放在後牆則跟其他北牆門同尺寸，劇情上也像演員從後台走上舞台。**這點需要作者確認。**
- 化妝間門、後台通化妝間的門、巷子後門：保留位置，但重新生成，跟新的門同一個尺寸規格；後台通化妝間的那扇原本只有 1.0×2.0 格，太小。
- 做法：每扇門單獨生成成「含門框的門」，程式統一縮成 1.7×2.9 格（生成圖比例 0.54–0.60，目標 0.59，形變 ≤ 8%），貼到那面牆的連續牆面上、下緣貼齊地面。後台陽台前緣整排先合成一張連續長圖（欄杆與壓條不中斷），再貼兩扇門、照格子切段，沒有接縫。
- 觸發點與落點：每扇門前兩格都是觸發點；arrive 落在觸發點前一格，不踩觸發格（`tests/map_check.py` 會驗，踩到就會彈回去）。

**門的閘門**（輸出 `evidence/door-gate-control.txt`）
- 設計閘門（`layout.check`）：門前觸發格要走得到、正北方那格要是實心的牆（門嵌在牆裡）、不能貼在地圖左右外緣。四張地圖全過；負控制：門放在左外緣、門前格正北方不是牆、門前格在牆上，三種都會被抓到。
- 新增的空洞閘門（`layout.check`）：走得到的格子一定要有地面。這是這輪我自己看圖才發現的 bug：後台一樓縮成 3 列後，東側第 10–11 列沒有任何地面也沒有牆，主角可以走進黑色空洞。現在補上實心外牆，閘門的負控制能抓到舊的設定。
- 圖面閘門（`art/mapgen.py audit`）：六種門都不貼邊、不傾斜（下緣傾斜 ≤ 0.06 度）、比例在 0.45–0.78 之間。

**對照圖**：`doors-before-after.jpg`（六扇門左舊右新）、`doors-in-engine.jpg`（主角站在每扇門前，引擎裡的畫面）。

## 機械驗收結果（原始輸出在 `evidence/`）

**物件閘門**（`evidence/audit-<map>.txt`）：下緣傾斜最大 0.74 度（機車）、其餘 ≤ 0.3 度；沒有貼邊被切；比例都在可接受範圍；遮擋牆與牆面不透明度 ≥ 97%。切完後每個物件都貼齊圖框下緣。
**地面閘門**：四張地面與設計格子的重疊度（IoU）都是 1.0。
**樓梯閘門（2026-10-20 修正）**：先前我用「踏階邊緣數」，把木板的板縫也算進去，A 段其實是一整塊平木板卻被判合格，閘門失效。現在改成沿樓梯縱向取亮度剖面，數「立面」＝夠深（低於踏面亮度 55%）又夠寬（≥ 9 px，約 0.14 格）的暗帶，板縫只有 1 到 5 px 寬，不算；每段露出來的樓梯要 ≥ 每格 0.9 條。控制實驗（`evidence/stairs-gate-control.txt`）：原本的 A 段（平木板）立面 0 條、暗帶寬只有 [1, 1, 5]，判不合格；B 段立面 9 條、暗帶寬約 19 到 20，判合格；另一張更早生成、兩段都是真階梯的圖也判合格。現在 A 段是用 B 段的階梯從上緣對齊貼過去的（`fix_stairs`），兩段 5 與 9 條立面，都合格。
**遮擋**（`evidence/occl-<map>.txt`）：後台走到轉折與 B 段北半的 13 格是 100% 整個人被藏起來，A 段與 B 段沒被擋住的格子都看得見（被蓋住 ≤ 4%）；負控制（拿掉轉折牆與 B 上段牆）後沒有任何一格被藏。其餘三張地圖沒有任何格子會讓人整個消失，也沒有被蓋超過 45% 的格子。
**靜態**（`evidence/map_check.txt`）：四張地圖每個事件與導引目標都走得到，所有跳轉落點都不在牆上、也不會剛好落在另一個 touch 事件上（會彈回去）。負控制：把側台門的觸發點放回牆格，檢查會抓到。
**實機走路**（`evidence/map_walk.txt`）：十一條路線全過（新增兩條長距離：從三排十四號走回舞台後牆的門、從巷子盡頭走回後門），包含二樓→U 型樓梯→一樓→側台門→觀眾席（約 10 秒，連拍證明人在轉折被擋住、在 B 段上緣重新出現，見 `backstage-stairs-walk.jpg`；樓梯井放大圖 `backstage-stairs-zoom.jpg`）。負控制：側台門放回牆格，引擎連任務都不給，測試失敗。

重產次數：化妝間 16 次生成呼叫（含重試）、後台 22、觀眾席 12、巷子 8，另外四張定錨各 1 次，地面共 7 次（後台地面因為 IoU 與樓梯閘門重產了 2 次）。

## 我自己覺得還不夠好的地方

1. **門在引擎的燈光下偏暗**：後台磚牆上兩扇門（尤其鋼門）在遊戲裡對比不高，燈光（`_env` 的光源）只換了座標，沒有逐一調亮度。
2. **後台陽台欄杆這次生成得偏細**：整排合成後欄杆跟後面的木地板對比比上一版低，遠看還是欄杆，但不如舊版清楚。欄杆右端有一根柱子的位置、燈的間距不是完全等距（長條是鏡射接長的）。
3. **舞台後牆的門是疊貼在紅絨幕牆面上的**：門兩側的幕簾是底下牆面的一部分，不是為了門「束起」的幕，看起來像門立在幕前，不像門嵌在幕後牆裡。
4. **一般牆上的門（化妝間、後台二樓、巷子、舞台）是「牆面切片＋貼上去的門」**，門貼上去的邊緣跟牆面有輕微色差；後台磚牆那兩扇是整排合成，沒有這個問題。
5. **門的大小是程式縮放成一致的**（形變 ≤ 8%），不是模型畫成一致。門板高度跟人物比：主角約 3.4 格，門含框約 2.9 格，仍比人矮一點，這是這個相機慣例（牆壓縮到約六成）的限制。
6. **後台一樓只剩 3 列**，比之前擠；器材箱與工作桌都貼在最下面。
7. **牆段接縫仍看得到**：化妝間北牆的窗、純牆各自生成，色調與護壁高低有一點差，已經用「比框寬就裁、比框窄就鏡射補」對齊高度並去掉去背邊，縫線不見，但色差還在。
8. **A 段與 B 段的階梯是同一份貼圖**（A 段從 B 段複製而來），兩段完全一樣，看得出是重複的。樓梯兩側還有幾塊純黑的空區，是樓梯井外的實心區，沒畫東西。
9. **樓梯井牆是兩片分開生成的**（拱門牆與牆墩），讀起來是一個樓梯井，但不是一體成形。
10. **觀眾席只畫三排座位**（原本四排，為了讓出舞台木裙的高度），後面是空的紅地毯；一千個座位畫不完，是設計時就決定的。
11. **窗邊長凳比設計矮**（生成圖比框寬扁，按寬縮放後高度只有框的 62%），不影響佔地。
12. **地毯位置與設計格子差約 0.4 格**（地面是生成的，對位只能保證地板範圍，內部花紋位置不保證）；地毯不擋路，沒有物件靠它定位，所以沒處理。
13. 手機直式沒有驗。

## 需要作者拍板

- **觀眾席通後台的門放在舞台後牆，不是舞台前緣**（理由見「門」一節）。如果作者就是要前緣，舞台木裙要加高到至少 4 格，座位要再少一排，要先說。
- 後台 U 型樓梯的視覺：轉折在北端、牆擋住（人整個消失）、B 段南半才現身。這是照作者畫的路線與 ASCII 圖做的，**如果作者想像的樣子不同，要先說，因為遮擋牆的尺寸與地面樓梯是連動的**。
- 化妝間新增了一張長沙發（南邊），是我為了讓南邊不空加的，不要可以刪（改設計檔一行）。
- 觀眾席要不要補後排座位或剪影，讓畫面不偏空。

## 給主對話的接線事項

- `src/build.py` **不需要改**：它呼叫 `maps.all_maps()`，名稱沒變；`assets/maps/<map>_ground.webp` 與 `assets/objects/<map>/<物件名>.webp` 路徑沒變。
- 後台地圖變成 24×16（一樓 3 列），巷子 18×12，所有 arrive 座標與導引已在 `src/maps.py` 一併改好；每扇門前兩格都是觸發點（id 與 id-b），劇本代號沒動。
- 自由圖片的前後順序靠「圖框下緣那一列」，所以 `sort` 比圖框下緣大的遮擋牆，圖檔底部有透明列（`src/layout.py` 的 `vis`／`frame`）。
- 重 build 後建議跑：`python3 tests/map_check.py`、`PROJECT=dist/project.json node tests/map_walk.mjs`、`python3 art/occl_check.py backstage`。
- `README.md`（repo 根目錄）還沒有提到 `art/mapgen.py` 與這些測試，需要主對話或文件分工的人補一行。
