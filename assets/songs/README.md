# 歌曲：放檔、切段、接進遊戲

三首歌由作者在 Suno 製作。放進這個資料夾以後，一個指令切段、處理、接進遊戲。

## 要放的三個檔

| 檔名（照這個命名） | 歌 | 歌詞來源 |
|---|---|---|
| `餘燼.mp3` | 〈餘燼〉 | `canon/歌詞.md` |
| `晚安台南.mp3` | 〈晚安，台南〉（檔名沒有逗號） | `canon/歌詞.md` |
| `港邊的燈.mp3` | 〈港邊的燈〉 | `canon/歌詞.md` |

放哪幾首都可以，沒放的歌就略過，對應的位置維持沒有歌的樣子。

## 放好之後跑

    python3 src/songs_cut.py --build

等於先切段（`python3 src/songs_cut.py`）再 `python3 src/build.py`。需要共用 whisper-server（沒開的話工具會自己用 `mori-whisper-serve --ensure` 拉起 large-v3-turbo，第一次載模型要等幾十秒）。

輸出在 `assets/songs/cuts/`：切好的小檔 mp3 加 `manifest.json`。跑完看終端機：每一段開頭是 `OK` 或 `FAIL`。`FAIL` 的段落不會被接進遊戲（建置時會印「略過」），診斷會印在那一行底下。

只重切某幾段：`python3 src/songs_cut.py --only ember_b1,night_sc --build`。

## 歌要符合什麼

評歌標準在 `canon/歌詞.md` 最後。接線需要的條件，工具靠這些才切得準：

1. 歌詞照 `canon/歌詞.md` 的順序唱，沒有跳句、重排段落。對齊用「順序約束」，副歌三次不會黏到同一次，但段落順序亂了就對不上，工具會報「歌詞對不上轉錄」。
2. 人聲要聽得清楚（工具靠語音辨識取每句的時間；字以歌詞檔為準）。
3. 句與句之間要有一點人聲停頓或氣口，切點才有地方落。
4. 〈晚安，台南〉第一、二段主歌只有鋼琴、速度自由（高潮那一刻要在第二段結尾收掉）。
5. 〈餘燼〉有 Final Chorus（第三次副歌，歌詞是「就算我認不出你／也請你 坐在那裡」那一版）。
6. 〈港邊的燈〉台語唸不準沒關係：它只做成老收音機的一小段，辨識與驗證對它放寬。

## 實際接線時的限制（先知道）

- **歌詞自動前進只能用固定間隔。** Larch 的 `autoAdvance` 只有卡片層一個 `delayMs`，逐句沒有各自的間隔。工具把歌詞分組（一張畫面 1 到 3 句），挑一個 delay，讓換頁時間貼近每句開唱的時間；前奏與間奏用只寫一個音符符號的畫面撐時間。建置時會印每張歌卡的 delay、畫面數與平均誤差。誤差來源：歌句長短不一但間隔固定；打字效果的時間；音檔載入到出聲的延遲。
- 歌卡設成「無法打斷」（玩家點了不會跳頁），不然歌詞會跑在歌前面。想允許跳過：`src/songs.py` 的 `UNINTERRUPTIBLE = False`。
- 歌卡是把原本那張卡切成三張：前（原代號）、歌（`代號__song`）、後（`代號__post`）。劇本文字不動；歌詞多於劇本的地方（`ending_b1` 的歌是整首，劇本只寫到第一次副歌；`concert` 的歌有兩段主歌，劇本只寫第一段），多出來的句子取自 `canon/歌詞.md`。
- 地圖調查點觸發的卡（`m_radio_on`、`mem0_market`）換不了曲，所以收音機歌用逐句 `sfxUrl`。sfx 只在當句播，玩家翻頁就停。
- 沒有 `manifest.json` 時 `src/songs.py` 什麼都不做，build 跟沒有歌的時候一樣。

## 驗證做了什麼

每段切點：不在字中間、落在句縫的能量低點；切好的檔讀回，頭 3 秒與尾 3 秒用語音辨識比對預期那句；另外拿錯的句子當負控制，分數要明顯較低。收音機版另外檢查單聲道與頻寬。結果在 `manifest.json` 每段的 `verify`。

## 測試用的替身

`_fixture/` 是用語音合成念歌詞做的替身，只用來測流程，不是正式歌檔，不進 git。`SONGS_DIR=assets/songs/_fixture python3 src/songs_cut.py` 才會處理它；預設只讀這一層的 `*.mp3`。
